# Documentation and release-readiness audit, 2026-10-08

A dated snapshot, not a living document. It checks the claims in
`README.md`, `docs/DEVELOPMENT.md`, `HANDOFF.md` and every
`docs/*-STATUS.md` against the code and tests on elegy `main` at
`e975fe4` (after elegy #43), with the stars-elegy public record on `main`
at `58a9b58` (after stars-elegy #116). It changes no other file. The fixes
it lists are for later, small PRs, each made by the lane that owns the
file.

Every number below comes from these commands, run on `e975fe4` with Go
1.24.7:

```sh
go vet ./...                                  # clean
go test -count=1 ./...                        # all five packages ok
go test -count=1 -run Confirmed ./...         # all five packages ok
go test -count=1 -run TestParityVectors -v ./engine
go test -count=1 -run TestUGVectors -v ./newgame
gofmt -l .                                    # nothing listed
```

"Verified" means checked in the code or test output named. "Inferred"
means read from the code but not exercised by a test.

## 2. Capabilities

### Implemented, with oracle-backed tests

- **Peaceful kernel**: habitability, maximum population, growth with the
  carry, resources and caps, mining and depletion, research (including
  Generalized Research and slower tech), production queues with Auto
  Alchemy and the auto items (KERNEL-STATUS.md table).
- **Production of ships, starbases, packets and terraforming**: launch,
  route warp, the 512-fleet limit, starbase replacement
  (ORDERS-LAYER-STATUS.md "Ships leaving production").
- **Movement and fuel**: chases, refuelling, ram scoops, fuel
  generators; LEGACY BUG fuel wrap.
- **Combat**: the battle phase, salvage, repair, tech from battle
  (COMBAT-STATUS.md).
- **Takeover**: bombing, unloads, colonist drops, ground combat,
  colonization, capture.
- **Scanning**: `PlayerView` per player each year, from a pure function
  of the post-turn game (SCANNING-STATUS.md).
- **Scores, victory flags, deciding the game, public scores** (KX-003,
  KX-004).
- **Random events**: comets, climate change, new minerals; the Trader's
  appearance.
- **Space objects**: minefields, wormholes, the Mystery Trader, packets,
  stargates and salvage, wired at KERNEL.md's steps
  (OBJECTS-STATUS.md).
- **Terraforming, Orbital Adjusters, Claim Adjuster drift and remote
  mining** (TERRAFORM-STATUS.md).
- **Orders layer**: research, battle plans, designs (read, edit,
  delete), cargo (own and cross-owner), waypoints with
  route/patrol/transfer/colonize/merge/transport-unload tasks, repeat,
  rename, merge, split, ship moves, queue replace, planet settings,
  relations; the replay shuffle and file acceptance.
- **New games**: galaxy, homeworlds, starting tech, players, designs,
  fleets, wormholes, built-in computer races; UG vectors (section 3).
- **Races**: advantage points, repairs, creation check, Random race, the
  yearly check wired into the turn.
- **Component table**: 239 rows, hash-checked against stars-elegy.

### Partially implemented

- **Waypoint tasks**: lay mines and remote mining run in the turn but
  `validTask` refuses them in an order (`ErrNotModelled`), so no player
  can give them except through state built directly. Load actions
  (load all, fill to, wait for, set amount to, set waypoint to) and
  scrap are not modelled (15 + 15 parity cases skip on them).
- **Minefield detonate order**: always refused.
- **Mystery Trader**: moves, appears, meets; trades with computer players
  use PLACEHOLDER levels; players never own Trader items.
- **Player views**: the engine computes estimates, headings and design
  disclosure, but the harness compares only report levels, starbases and
  object sight; `other_players`, `player` and `design` blocks and five
  view fields are not compared (section 3).
- **Rulesets**: `Ruleset` is an empty interface and `Jrc3()` carries
  nothing (`engine/turn.go:187-192`). Compatibility switches are
  compile-time constants in `engine/` and mutable package variables in
  `objects/` and `newgame/`, so a game cannot choose them and the
  `objects`/`newgame` ones are process-wide.
- **Messages**: the turn emits typed `Event`s; message text is Elegy's
  own and partial (for example, nothing for an adjuster or remote miner
  that changed nothing).
- **Names**: planet names and computer-player names are placeholders.
- **Following fleets** (KERNEL.md step 1a.3): not kept; a waypoint aimed
  at a fleet takes its position.

### Not implemented

- **Save and load**: no serialization of `engine.Game`.
- **A game driver**: no command, CLI or loop that creates a game, takes
  orders and advances years. The only multi-year runs are tests:
  `TestElegyDecisionGameRuns` (16 players, 5 years, no orders) and the PG
  homeworld 2407–2436.
- **An order input format**: orders exist only as Go values.
- **Computer players**: built-in races exist; no planner.
- **Client-side estimates** (159 `client_estimate` cases), the client's
  report history, race files and checksums, the new-game wizard's
  unseeded games, original-file import or export, any UI.
- **Rules listed as not modelled**: ancient artifacts, Super Stealth
  research stealing, the duplicate-serial penalty, the AR colony's
  starbase (below), unloads into fleets or salvage.

### Blocks a long game (inferred from code, not exercised)

An Alternate Reality player that colonizes or captures a habitable
planet gets no starbase (`newColony`, `engine/takeover.go:321-343`). The
next `GenerateTurn` then returns `ZeroMaxPopulationError`
(`checkGenerable`, `engine/turn.go:31-43`) and the game cannot advance.
In the original game the colony gets its owner's first starbase design
(TAKEOVER-STATUS.md line 78). The error itself is the Elegy decision for
a state the original game crashes on. Here, though, the state arises only
because of the missing starbase. Any multi-year game with an AR player
will hit this. It is lane A's to fix.

### Smoke probe (one observation, not a test)

A throwaway test, not committed, generated a Medium/Normal galaxy with
all 16 PRTs as human players (seed 8). It ran 50 years through
`GenerateTurn` with no orders (turn seed 99), twice. Both runs reached
2450 with no error and gave the same digest of every planet's owner and
population each year. This is one seed and no orders: it shows the turn
runs for 50 years in that setup. It does not show determinism or
validity in general.

## 4. Reproducing today

```sh
go test ./...                                   # CI runs only this
go test -run Confirmed ./...                    # ground-truth tests only
go test -run TestParityVectors -v ./engine      # per-corpus tally, then every non-passing case
PARITY_BASELINE=write go test -run TestParityVectors ./engine   # refresh baseline.txt after checking each change
go test -run TestUGVectors -v ./newgame         # new-game vectors
```

- `go.mod` says Go 1.23.0. CI (`.github/workflows/ci.yml`) runs
  `go test ./...` only, with no `go vet` or `gofmt` check. Both are
  clean today.
- To update the vectors, copy stars-elegy `vectors/` into
  `engine/testdata/vectors` and keep `baseline.txt` and `FORMAT.md`. The
  copy is at `6fba6a3` and lags stars-elegy #116.
- There is no way to play or run a game outside a Go test.
